How to deploy a website from GitHub for free

GitHub · Any stack7 min readUpdated 21 November 2026

GitHub keeps your code safe, but it doesn't run it. GitHub Pages can serve plain HTML files, and that's where it stops: no Flask, no Express, no database calls. To get a real app online you need something that pulls the repository, builds it and keeps it running. Here's the whole path on Shipzo, from the repo link to automatic redeploys.

Quick answer
  1. Push your project to GitHub (public, or private with a read-only token).
  2. Paste the repository link into Shipzo. It works out the stack, runs your tests and builds a container.
  3. The site goes live at https://your-project.shipzo.tech.
  4. Every later git push redeploys it within about a minute, and a broken commit never replaces the working version.

What kind of repository works

You don't write a config file. Shipzo looks at the files in your repository and decides how to build it:

If the repo has…It is deployed as
DockerfileYour own container, built exactly as written
package.json with nextA Next.js server (server-side rendering works)
package.json with a build script (React, Vite, Vue, Angular, Svelte)A static site served by nginx
package.json with Express, Fastify, Koa or NestJSA Node.js server
requirements.txt plus manage.pyDjango, run with gunicorn
requirements.txt naming fastapi or streamlitFastAPI with uvicorn, or Streamlit
Any other requirements.txtFlask or another WSGI app, run with gunicorn
go.modA compiled Go server
index.html and no server codeA static website
One rule for server apps: listen on 0.0.0.0 and on the port given in the PORT environment variable. Most frameworks do this already. A hard-coded localhost:5000 is the most common reason a deploy fails its health check.

Step 1: Paste the repository link

  1. Create a free Shipzo account and open New deployment.
  2. Paste the link. Any of these work: https://github.com/you/my-app, you/my-app, or a link to a folder such as https://github.com/you/my-app/tree/main/frontend.
  3. Leave Branch empty to use the default branch, or type another one (for example dev).
  4. If the app lives in a sub-folder of a bigger repository, put that folder in Root directory, for example backend/.

The project name becomes your address, so a project called library-system ends up at https://library-system.shipzo.tech.

Private repositories

For a private repo, Shipzo needs a token that can read it. Create a fine-grained token on GitHub:

  1. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Under Repository access, choose Only select repositories and pick the one you are deploying.
  3. Under Permissions, set Contents to Read-only. Nothing else is needed.

Paste the token into the Private repository? field of the form. It is masked in every log, and because it can only read one repository, it can't be used to change your code.

Step 2: What happens when you press Deploy

StageWhat it does
Fetch sourceMakes a shallow clone of your branch and notes the commit
Detect & scanPicks the stack and warns about committed secrets such as .env files, private keys or API keys
TestRuns npm test, pytest or go test in a clean container if you have tests; a failure stops the release
BuildUses your Dockerfile, or writes one for your stack, and builds the image
DeployStarts the new version next to the old one, with your plan's memory and CPU limits
Health checkSends requests for up to 120 seconds until the app answers
Go liveMoves traffic to the new version and stops the old one

You can watch each stage and the full build log live on the project page.

Step 3: Redeploy automatically on every push

Continuous deployment is on by default. Shipzo checks your branch every 60 seconds and deploys any new commit, so you don't have to set anything up. If a commit fails its tests, it isn't retried over and over; push a fix and the new commit is picked up.

If you'd rather not wait up to a minute, add a webhook:

  1. In Shipzo, open the project → Settings → Deploy hook & GitHub webhook, and copy the hook URL.
  2. In GitHub, open the repo → Settings → Webhooks → Add webhook.
  3. Paste the URL as Payload URL, choose application/json as the content type and Just the push event.

A third option: the DevOps files tab contains a GitHub Actions workflow written for your project. Commit it as .github/workflows/shipstack.yml and your tests also run on GitHub for every pull request.

When a deploy goes wrong

A new version only receives traffic after it passes its tests and health check. If either fails, the previous version keeps serving and the dashboard tells you why. If something slips through and the new version misbehaves, open Deployments and roll back to any of the last five successful releases. Rollbacks reuse the image that was already built, so they take seconds.

Common errors and fixes

ProblemFix

Frequently asked questions

Isn't GitHub Pages enough?

For a site made only of HTML, CSS and JavaScript, GitHub Pages works. As soon as the project has server code, such as Flask, Express, Django or an API, it needs a host that runs it.

Can I deploy just one folder of my repository?

Yes. Put the folder in Root directory when you create the project, or paste a GitHub link that points at that folder.

Does it work with GitLab or Bitbucket?

Shipzo clones from GitHub. For code hosted elsewhere, download it as a ZIP and use Upload ZIP instead.

Is it free?

Yes. Shipzo is free during the beta, with up to 3 projects per account and no card required.
