How to deploy a MERN stack app for free

MERN · MongoDB · React · Node9 min readUpdated 21 November 2026

Most MERN projects are really two apps in one repository: an Express API and a React front end. The easiest way to deploy them is as two separate deployments that talk to each other over HTTPS, with the database on MongoDB Atlas.

Quick answer
  1. Keep the API and the front end in separate folders, for example backend/ and frontend/.
  2. Create a free MongoDB Atlas cluster and put its connection string in MONGODB_URI.
  3. Deploy backend/ first, then frontend/ with VITE_API_URL set to the backend address.
  4. Allow the front-end address in the backend's CORS settings.

The project layout

my-mern-app/
├── backend/
│   ├── package.json
│   ├── server.js
│   └── routes/
└── frontend/
    ├── package.json
    ├── vite.config.js
    └── src/

Both folders live in one GitHub repository. You will create two Shipzo projects from it, each pointing at its own folder.

Step 1: Set up the database on MongoDB Atlas

  1. Create a free cluster on MongoDB Atlas.
  2. Under Database Access, add a user with a password.
  3. Under Network Access, allow access from anywhere (0.0.0.0/0) or from the server's IP address. If you skip this, the connection times out.
  4. Click Connect → Drivers and copy the connection string. It starts with mongodb+srv://.

mongodb://localhost:27017 only works on your own computer, so the deployed app must use the Atlas string.

Step 2: Prepare the backend

backend/server.js

const express = require('express');
const mongoose = require('mongoose');
const cors = require('cors');

const app = express();
app.use(express.json());
app.use(cors({ origin: process.env.FRONTEND_URL }));

app.get('/', (req, res) => res.json({ status: 'ok' }));
app.use('/api/notes', require('./routes/notes'));

mongoose.connect(process.env.MONGODB_URI)
  .then(() => console.log('MongoDB connected'))
  .catch((err) => { console.error(err); process.exit(1); });

const PORT = process.env.PORT || 5000;
app.listen(PORT, () => console.log(`API on ${PORT}`));

In backend/package.json, make sure "start": "node server.js" is set (not nodemon), and that express, mongoose and cors are in dependencies.

Step 3: Prepare the front end

Never hard-code http://localhost:5000 in your React code. Read the API address from a build-time variable instead:

frontend/src/api.js

const API = import.meta.env.VITE_API_URL;

export async function getNotes() {
  const res = await fetch(`${API}/api/notes`);
  return res.json();
}

For local development, put VITE_API_URL=http://localhost:5000 in frontend/.env (and keep .env out of Git). If you used Create React App instead of Vite, the variable is REACT_APP_API_URL and you read it with process.env.REACT_APP_API_URL.

Step 4: Deploy two projects

Project 1, the API. Open New deployment, paste the repository link, set Root directory to backend/ and name the project, for example notes-api. Add two environment variables:

MONGODB_URI=mongodb+srv://user:password@cluster0.xxxxx.mongodb.net/notes
FRONTEND_URL=https://notes.shipzo.tech

Deploy. The API is now at https://notes-api.shipzo.tech.

Project 2, the front end. Create another deployment from the same repository with Root directory set to frontend/, name it notes, and add:

VITE_API_URL=https://notes-api.shipzo.tech

Deploy. The site is at https://notes.shipzo.tech. Refreshing deep links such as /notes/42 works without extra configuration, because Shipzo serves index.html for client-side routes.

From now on, a git push redeploys both projects. The beta allows three projects per account, so a MERN app uses two of them.

Common errors and fixes

ProblemFix
CORS error in the browser consoleFRONTEND_URL must exactly match the front-end address, with https:// and no trailing slash.
Front end still calls localhostVITE_API_URL is built in. Set it in the front-end project, then redeploy that project.
MongooseServerSelectionErrorAtlas is blocking the connection. Check Network Access.
Mixed content blockedThe API address must start with https://.
Health check timed out on the APIUse process.env.PORT instead of a fixed port.

Frequently asked questions

Can I deploy the whole MERN app as one project?

Yes, if Express serves the built React files with express.static. Then there is one project, one address and no CORS setup, but every change rebuilds both halves.

Is MongoDB Atlas free?

Atlas has a free M0 tier with 512 MB of storage, which is plenty for student projects and demos.

Does Socket.io work?

Yes. WebSocket connections are passed through to your app.

Is hosting free?

Yes, during the beta, with up to 3 projects per account and no card.
