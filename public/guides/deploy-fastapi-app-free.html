How to deploy a FastAPI app for free

Python · FastAPI6 min readUpdated 21 November 2026

FastAPI is quick to write and quick to run. Deploying it mostly comes down to telling the server where your app object lives and which port to use. This is the shortest path from uvicorn main:app --reload to a public API with HTTPS and interactive docs.

Quick answer
  1. Create the app in main.py (or app.py) as app = FastAPI().
  2. List fastapi in requirements.txt. Shipzo installs uvicorn and starts it on the right port.
  3. Allow your front end's address with CORSMiddleware.
  4. Push to GitHub and deploy. The docs appear at https://your-api.shipzo.tech/docs.

How Shipzo starts a FastAPI app

When requirements.txt mentions fastapi, Shipzo looks for your code in this order: app.py, main.py, wsgi.py, application.py, server.py, api.py. It finds the variable you assigned FastAPI() to and starts uvicorn main:app --host 0.0.0.0 --port $PORT on Python 3.12. uvicorn is installed for you even if it isn't in your requirements.

If your app lives inside a package, for example app/main.py, set a custom Start command in Settings: uvicorn app.main:app --host 0.0.0.0 --port $PORT.

Step 1: The app

main.py

import os
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI(title="My API")

app.add_middleware(
    CORSMiddleware,
    allow_origins=[os.environ.get("FRONTEND_URL", "http://localhost:5173")],
    allow_methods=["*"],
    allow_headers=["*"],
)

@app.get("/")
def root():
    return {"status": "ok"}

@app.get("/items/{item_id}")
def read_item(item_id: int, q: str | None = None):
    return {"item_id": item_id, "q": q}

requirements.txt

fastapi>=0.115
uvicorn[standard]>=0.30
httpx>=0.27        # only needed for the tests below

The root route isn't strictly required. Shipzo's health check accepts any response below 500, so even a 404 at / counts as healthy. Still, a small / route makes the uptime and response-time charts on your dashboard meaningful.

Step 2: Secrets and databases

Read keys and connection strings with os.environ, then add the values in Shipzo under Settings → Environment variables. They are injected at start-up and masked in logs. For data that must survive a redeploy, use a hosted database such as Neon or Supabase (PostgreSQL) or MongoDB Atlas. A SQLite file inside the container is reset on every deploy.

Step 3 (optional): Add a test

Any file named test_*.py makes Shipzo run pytest before each deploy, and a failing test stops the release:

test_main.py

from fastapi.testclient import TestClient
from main import app

client = TestClient(app)

def test_root():
    assert client.get("/").status_code == 200

def test_item():
    assert client.get("/items/5?q=hi").json() == {"item_id": 5, "q": "hi"}

Step 4: Push and deploy

git add .
git commit -m "FastAPI app"
git push

Open New deployment in Shipzo, paste the repository link and press Deploy. When it is live, open https://your-api.shipzo.tech/docs for the Swagger UI or /redoc for ReDoc. If a React or Vue front end calls this API, set FRONTEND_URL to that front end's address so CORS lets it through.

Common errors and fixes

ErrorFix
Error loading ASGI app / Could not import moduleThe file or variable name doesn't match. Use main.py with app = FastAPI(), or set the start command.
Browser shows a CORS errorAdd the exact front-end address, for example https://my-site.shipzo.tech, to allow_origins.
ModuleNotFoundErrorAdd the missing package to requirements.txt and push again.
App exits during start-upRead the end of the build log. A missing environment variable is the usual cause.

Frequently asked questions

Do the /docs and /redoc pages work after deployment?

Yes. FastAPI serves them from your app, so they are available at your project address.

Can I use WebSockets?

Yes. WebSocket connections are passed through to your app.

Can I run several uvicorn workers?

Yes. Set a custom start command such as uvicorn main:app --host 0.0.0.0 --port $PORT --workers 2, and pick a plan with enough memory.
