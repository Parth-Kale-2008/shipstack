How to deploy a Django app for free

Python · Django9 min readUpdated 21 November 2026

Django runs happily with python manage.py runserver on your laptop. On a real server, four things change: the allowed hosts, the static files, the database and the migrations. Sort those out once and every deploy after that is a git push.

Quick answer
  1. Read SECRET_KEY, DEBUG and DATABASE_URL from environment variables.
  2. Add .shipzo.tech to ALLOWED_HOSTS and https://*.shipzo.tech to CSRF_TRUSTED_ORIGINS.
  3. Serve static files with WhiteNoise. Shipzo runs collectstatic during the build.
  4. Set the start command so migrations run before gunicorn starts.

How Shipzo runs a Django project

Shipzo recognises Django when it finds manage.py next to requirements.txt. It locates the wsgi.py inside your project folder (for example mysite/wsgi.py), runs python manage.py collectstatic --noinput while building the container, and starts gunicorn mysite.wsgi:application with two workers on Python 3.12. You don't need a Procfile or a Dockerfile.

my-django-project/
├── manage.py
├── requirements.txt
├── mysite/
│   ├── settings.py
│   ├── urls.py
│   └── wsgi.py
└── blog/               # your apps

Step 1: Production settings

These are the lines that usually need changing in settings.py:

mysite/settings.py

import os
from pathlib import Path
import dj_database_url

BASE_DIR = Path(__file__).resolve().parent.parent

SECRET_KEY = os.environ.get("SECRET_KEY", "dev-only-change-me")
DEBUG = os.environ.get("DEBUG", "False") == "True"
ALLOWED_HOSTS = [".shipzo.tech", "localhost", "127.0.0.1"]
CSRF_TRUSTED_ORIGINS = ["https://*.shipzo.tech"]

MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "whitenoise.middleware.WhiteNoiseMiddleware",
    # ... the rest of your middleware stays as it was
]

STATIC_URL = "static/"
STATIC_ROOT = BASE_DIR / "staticfiles"

DATABASES = {
    "default": dj_database_url.config(
        default=f"sqlite:///{BASE_DIR / 'db.sqlite3'}", conn_max_age=600
    )
}

WhiteNoise lets gunicorn serve your CSS, JavaScript and the admin's styles. Without it, the site loads but looks unstyled, because Django doesn't serve static files when DEBUG is off.

Don't turn on SECURE_SSL_REDIRECT. Shipzo already serves your app over HTTPS and passes requests to it internally over plain HTTP. With that setting on, Django keeps redirecting to HTTPS and the browser ends up in a redirect loop.

requirements.txt

Django>=5.0,<6
gunicorn>=22
whitenoise>=6.6
dj-database-url>=2.1
psycopg[binary]>=3.1

Step 2: Use a hosted database

Every deploy starts from a fresh container, so a db.sqlite3 file inside the project is reset each time and anything users saved is lost. Use a free hosted PostgreSQL database instead, such as Neon or Supabase:

  1. Create a database and copy its connection string (it starts with postgresql://).
  2. In Shipzo, open Settings → Environment variables and add DATABASE_URL=postgresql://....
  3. Add a real secret key as well. Generate one with python -c "import secrets; print(secrets.token_urlsafe(50))" and save it as SECRET_KEY.

Variable values are injected when the app starts and masked in every log.

Step 3: Run migrations on every deploy

Shipzo doesn't run migrate on its own, so add it to the start command. Open Settings → Build & runtime overrides and set Start command to:

python manage.py migrate --noinput && gunicorn mysite.wsgi:application --bind 0.0.0.0:$PORT --workers 2

Replace mysite with the name of the folder that holds your wsgi.py. To create an admin user, point your local copy at the same database (set DATABASE_URL in your terminal) and run python manage.py createsuperuser on your own computer.

Step 4: Push and deploy

git add .
git commit -m "Production settings"
git push

In Shipzo, open New deployment, paste the repository link and press Deploy. The Starter plan is enough for a small site; for bigger projects with many apps, choose Standard. Your project is live at https://your-project.shipzo.tech, and later pushes redeploy it automatically.

Running your tests

Shipzo runs pytest before each deploy when it finds files named test_*.py or *_test.py. Django's default tests.py doesn't match that pattern, so rename it (for example to test_views.py), add pytest-django to your requirements and create a pytest.ini:

pytest.ini

[pytest]
DJANGO_SETTINGS_MODULE = mysite.settings

If a test fails, the release stops and the version that is already live keeps running.

Common errors and fixes

ErrorFix
DisallowedHost / Bad Request (400)Add .shipzo.tech to ALLOWED_HOSTS.
CSRF verification failed (403) when submitting a formAdd https://*.shipzo.tech to CSRF_TRUSTED_ORIGINS.
Pages load without CSS, admin looks brokenAdd WhiteNoise to MIDDLEWARE and set STATIC_ROOT.
no such table or relation does not existMigrations haven't run. Set the start command from Step 3.
Too many redirectsRemove SECURE_SSL_REDIRECT = True.
Data disappears after a redeployYou are still on SQLite. Set DATABASE_URL to a hosted database.

Frequently asked questions

Do I need a Procfile or Dockerfile?

No. Shipzo detects Django from manage.py and writes the Dockerfile itself. You can see it in the DevOps files tab.

Can I deploy Django REST Framework APIs?

Yes. The steps are the same; an API project usually doesn't even need WhiteNoise unless it uses the browsable API or the admin.

Can I use MySQL instead of PostgreSQL?

Yes, any hosted database that dj-database-url understands works. Add the matching driver to requirements.txt. Free PostgreSQL from Neon or Supabase is the easiest option.

Will my site go to sleep when nobody visits?

No. Apps on Shipzo keep running, so the first visitor doesn't wait for a cold start.
