How to deploy a Docker container for free

Docker · Any language7 min readUpdated 21 November 2026

If your project has a Dockerfile, the host doesn't need to understand your framework. Shipzo builds the image exactly as written and runs it with HTTPS, monitoring and rollback. Ruby, Rust, Java, PHP or .NET: if it runs in a container and answers HTTP requests, it can be deployed.

Quick answer
  1. Keep the Dockerfile at the top of the repository, or of the root directory you choose.
  2. EXPOSE the port your app listens on. Shipzo also passes that number in the PORT variable.
  3. Listen on 0.0.0.0, not localhost.
  4. Use a multi-stage build and a .dockerignore to keep the image small.

How Shipzo uses your Dockerfile

  • The image is built exactly as written. Shipzo doesn't change your Dockerfile.
  • The port comes from the first EXPOSE line (3000 if there is none). The same number is passed to the container as the PORT environment variable.
  • The container runs with your plan's memory and CPU limits, a cap of 256 processes and no extra privileges. It is reachable only through https://your-app.shipzo.tech.
  • There is no separate test stage for Dockerfile projects. Run your tests inside the Dockerfile instead; if a RUN step fails, the build stops and the live version keeps running.

An example Dockerfile

A multi-stage build compiles and tests in one image, then copies only what is needed into a small final image:

Dockerfile

# 1. build and test
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build && npm test

# 2. small runtime image
FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY --from=build /app/package*.json ./
RUN npm ci --omit=dev
COPY --from=build /app/dist ./dist
EXPOSE 8080
CMD ["node", "dist/server.js"]

Inside the app, read the port with something like process.env.PORT || 8080 and listen on 0.0.0.0. Add a .dockerignore so local junk doesn't end up in the image:

.dockerignore

node_modules
.git
.env
*.log

What isn't supported

  • docker-compose with several services. Each Shipzo project runs one container. Deploy each service as its own project and use a hosted database.
  • Volumes. The filesystem starts fresh on every deploy, so store data in a database or object storage.
  • Privileged containers, host networking or fixed host ports.

Going the other way

For projects without a Dockerfile, Shipzo writes one for you. Open the DevOps files tab to see it, together with a docker-compose.yml and a GitHub Actions workflow. Commit them if you want to run the same container anywhere else. If your repository has a Dockerfile but you'd rather use Shipzo's, tick Ignore repository Dockerfile in Settings.

Common errors and fixes

ProblemFix
Health check timed outThe EXPOSE port doesn't match the port the app listens on, or the app binds to localhost.
Container keeps restartingIt is running out of memory. Choose a bigger plan or reduce memory use.
Build fails at a RUN stepOpen the build log; the failing command and its output are shown there.
permission denied when binding to port 80Non-root users can't use ports below 1024. Listen on 8080 and EXPOSE 8080.

Frequently asked questions

Can I use docker-compose?

Not with several services in one project. Deploy each service as a separate project and connect them over HTTPS.

Will Shipzo use my Dockerfile or its own?

Yours, if the repository has one. Tick Ignore repository Dockerfile in Settings to use the generated one instead.

Can I deploy Java, PHP, Ruby or Rust apps?

Yes, through a Dockerfile, as long as the app answers HTTP requests on the exposed port.

Is Docker hosting free?

Yes, during the beta, with up to 3 projects per account and no card.
